No cloud required

Off-Grid Intelligence

When the cloud went dark, the camps that kept their AI were the ones running it themselves. Ollama runs open language models on your own machine and serves them to your code. This manual takes you from install to a working prototype: a Camp Quartermaster app with chat, structured extraction, tools, document search and a web interface.

Who it's for

Engineers who want to prototype an AI feature in Python quickly, on their own hardware.

Time

60 to 90 minutes, mostly hands-on.

Bring

Python 3.10 or newer, 8 GB of RAM or more, and about 10 GB of free disk.

  • Data stays on the machine.

    Prompts and documents never leave your computer, which makes it easy to try ideas on sensitive material.

  • Offline and free per call.

    No API keys, no usage bill, no network. Iterate as fast as your hardware allows.

  • Your hardware sets the limits.

    Local models are smaller than frontier models. Prototype here, measure the quality, then decide where it should run.

Part 1 · Power up

Install Ollama and pull a model

Ollama runs as a background server on localhost:11434. The desktop app starts it for you; on Linux the installer sets it up as a service.

  1. Install Ollama. On macOS or Windows, download it from ollama.com/download. On Linux, run the install script shown here.
  2. Pull a model. llama3.2 is about 2 GB, supports tools, and runs on most laptops.
  3. Talk to it in the terminal to confirm it works. Type /bye to exit.
  4. Check the server. The URL should answer "Ollama is running."
  5. Set up Python in a virtual environment and install the client library.
# 1. Linux install (macOS and Windows: use the app)
curl -fsSL https://ollama.com/install.sh | sh

# 2. Pull a model
ollama pull llama3.2

# 3. Try it
ollama run llama3.2 "In one line: why boil water?"

# 4. Server check
curl http://localhost:11434

# 5. Python project
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install ollama pydantic
Part 2 · Pick your engine

Which model fits your machine

Rule of thumb: a model needs about its download size in memory, plus 2 to 6 GB for the context window. Set your memory and what you need the model to do. On a Mac, use total RAM; on a PC with a GPU, use the GPU's VRAM.

    Pocket checklist

    Ready to show the council

    • The model name, options and host live in one config file.
    • The system prompt lives in one place, not scattered through the code.
    • Every structured output is validated, and failures are counted.
    • The tool loop has a maximum number of rounds.
    • I've run at least 10 real inputs and written down what failed.
    • I've noted the hardware it ran on and how long a typical answer took.
    • I know whether this needs a bigger or hosted model, and the OpenAI-compatible swap is ready if so.
    Appendix · Pocket card

    Cheat sheet

    # models
ollama pull llama3.2        # download
ollama run llama3.2         # chat in the terminal (/bye to exit)
ollama list                 # what's downloaded
ollama ps                   # what's loaded, and whether it's on GPU or CPU
ollama show llama3.2        # details, context length, capabilities
ollama rm llama3.2          # delete
ollama serve                # start the server by hand (if the app isn't running)

# python
from ollama import chat, embed
r = chat(model="llama3.2", messages=[{"role": "user", "content": "..."}],
         options={"temperature": 0.2, "num_ctx": 8192})
r.message.content           # the reply
chat(..., stream=True)      # iterate chunks: chunk.message.content
chat(..., format=Model.model_json_schema())   # structured output
chat(..., tools=[python_function])            # tool calling
embed(model="nomic-embed-text", input=[...]).embeddings

# elsewhere
OLLAMA_HOST=http://other-machine:11434     # point the client at another server
OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
