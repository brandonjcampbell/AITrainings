Deep dive · after Field Manual 0

Line of Sight

A lookout on the wall doesn't watch everything equally. They scan, decide what matters, and report it. Attention does the same for every token in a language model: it looks back over the text, decides which earlier tokens are relevant, and pulls in their information. It's the mechanism that lets "it" know it means the radio. This manual works through the actual math, one step at a time, with numbers you can inspect.

Who it's for

Engineers, and anyone who finished Field Manual 0 and wants the real mechanism.

Time

About 60 minutes.

Bring

Comfort with vectors and a dot product. The calculator does the arithmetic.

Part 1 · The problem it solved

Why reading left to right wasn't enough

Earlier language models, recurrent neural networks, read one word at a time and squeezed everything so far into a single fixed-size memory vector. Long sentences overflowed it: by the end of a paragraph, the start was blurred. Attention was introduced in 2014 for translation, letting the model look back at every input word directly instead of relying on that one summary. In 2017 the paper Attention Is All You Need dropped the recurrence entirely and built the transformer from attention alone. Every major LLM since descends from it.

Recurrent

One rolling memory

Information from early words has to survive every step to reach the end. Reading is sequential, so training is slow.

Attention

Direct line of sight

Any token can look at any earlier token in one step, however far back. All positions are computed in parallel during training.

The cost

Every pair compared

Comparing every token with every other grows with the square of the length. Part 6 covers what that means for long contexts.

Part 2 · The intuition

Queries, keys and values

Each token produces three vectors from its embedding, using three learned weight matrices. Think of the camp radio net.

What I'm looking for

Query

The token's request. "I'm a pronoun; I'm looking for the noun I refer to."

What I can offer

Key

The token's call sign, which other tokens' queries are matched against. "I'm a noun, a physical object."

What I'll hand over

Value

The information passed on when a query matches the key. The match decides how much of each value gets through.

outputi = Σj ≤ i softmaxj( qi · kj / √d ) · vj

In words: compare my query with every earlier key, turn those scores into weights that add up to one, and take that weighted blend of the values. That blend is added to my vector, so I now carry information from the tokens I attended to.

Part 4 · Why divide by √d

Keeping softmax from saturating

The dot product of two random vectors grows with their dimension: its typical size is about √d. Feed large scores to softmax and it puts nearly all the weight on one token, and learning stalls because the gradients through softmax become tiny. Dividing by √d keeps scores in a workable range at any width. The demo draws random query and key vectors at the dimension you choose.

Part 5 · Many lookouts

Multi-head attention

One head can only form one blend per token. So each layer runs many heads in parallel, often 32 or more, each with its own query, key and value weights, and concatenates their outputs. Different heads end up tracking different relationships. Research into trained models has found heads like these. Pick one.

Induction heads, for engineers

Anthropic's 2022 interpretability research described induction heads: a pair of heads in different layers that implement "find the last time the current token appeared, look at what came next, and predict that." Given … A B … A, they push the model toward B.

The researchers found these heads form at the same point in training where models suddenly get better at in-context learning, and argued they're a major mechanism behind it. It's a concrete reason examples in a prompt (Field Manual 1, lever 4) work so well: the model is built to copy patterns it has just seen.

Part 6 · The price of long context

Quadratic scores and the KV cache

Two costs grow with context length. Computing attention compares every token with every earlier one, so work grows with n². During generation, the model stores every earlier token's keys and values (the KV cache) so it doesn't recompute them, and that memory grows linearly with n. Set a context length and a model shape.

Grouped-query attention

Many query heads share a smaller set of key and value heads. It shrinks the KV cache several times over with little quality loss, and is common in current open models. Move the slider from 64 to 8 to see the effect.

FlashAttention

Computes exact attention in tiles that stay in the GPU's fast on-chip memory, never writing the full n × n score matrix out. Same result, much less memory traffic, so long contexts become practical.

Windows and sparsity

Some layers attend only to a recent window, or to a selected subset of tokens, cutting the quadratic cost. Many long-context models mix these with full-attention layers.

Part 7 · In the field

What attention means for your prompts

Position matters

Details in the middle of a very long context get used less reliably than those near the start or end.

So: put long documents first and the question last, and keep the critical instruction near the end (FM 1, lever 7).

Order needs encoding

Attention by itself treats the input as an unordered set.

So: models add position information, today often with rotary embeddings (RoPE) that rotate queries and keys by position. Extending a model's context length mostly means adapting this.

Examples get copied

Models strongly continue patterns seen earlier in the context.

So: examples are powerful, and their surface quirks get copied too. Vary them (FM 1, lever 4).

Repeated prefixes are cheap

The KV cache for an identical prompt prefix can be reused across requests.

So: put stable content (system prompt, documents, tool definitions) first and changing content last. Prompt caching features in model APIs rely on this.

Long isn't free

Longer contexts cost more compute and memory, and add latency before the first token.

So: retrieve what's relevant (FM 7) rather than sending everything, and summarize finished work in agent sessions (FM 5).
