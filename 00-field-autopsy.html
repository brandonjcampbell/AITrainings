Know what you're dealing with

Field Autopsy

Every survivor learns how the threat works before trusting a plan against it. This manual opens up a large language model, layer by layer. The short version: an LLM is a function that takes text and returns a probability for every possible next token. It picks one, appends it, and runs again. Everything else, the helpful answers and the confident mistakes, follows from that loop.

Who it's for

Anyone using or building with LLMs. Each part has an optional deeper section for engineers.

Time

About 60 minutes.

Part 1 · Tokens

The model never sees letters

Text is cut into tokens: whole words, pieces of words, punctuation. Common words become one token; rare words split into several. Most tokenizers learn their pieces with byte-pair encoding (BPE): start from single characters, then repeatedly merge the pair that appears most often. Train a tiny tokenizer below on a few camp sentences.

Latest merges

This is real BPE, trained in your browser on about 40 words. Production tokenizers run the same algorithm on billions of words, usually over bytes, and end up with vocabularies of roughly 30,000 to 250,000 tokens.

Cost and limits

Prices and context windows are counted in tokens. In English, a token averages about four characters, or roughly three-quarters of a word. Other languages and code often take more tokens for the same meaning.

Spelling blind spots

Asking how many r's are in a word asks about letters the model never directly sees. It has to infer spelling from what it learned about each token.

Numbers

A long number may split into odd chunks, like 18 / 437 / 2. That's one reason arithmetic is better done with a tool.

Part 2 · Embeddings

Every token becomes a point in space

Each token ID is looked up in a table and turned into a long list of numbers, its embedding. Training arranges these so that tokens used in similar ways end up close together. Directions in this space come to mean things, like "is a person" or "is dangerous."

The map is a two-dimensional sketch. Real embeddings have hundreds to thousands of dimensions, and the model's internal vectors keep changing as they move through the layers, so a word's meaning gets refined by its context.

This is also how retrieval works in Field Manual 7: an embedding model turns a question and a document into vectors, and closeness means related meaning.

For engineers

The embedding table is a matrix of shape vocabulary size × model width. A token ID selects one row. Position information is added so word order matters, often with rotary position embeddings (RoPE), which rotate query and key vectors by an angle that depends on position. The resulting vectors form the residual stream that every later layer reads from and adds to.

Part 3 · Attention

Each token decides which others matter

Words mean different things in different sentences. Attention lets each token gather information from the tokens before it, weighted by relevance. Pick an ending and see where "it" looks.

Illustrative weights. A real model has many attention heads across dozens of layers, each tracking different relationships. Some follow grammar, some track what a pronoun refers to, some copy earlier text.

For engineers

Each token's vector is projected into a query, a key and a value. A token's query is compared with every earlier token's key; the scores are scaled and passed through softmax to become weights; the output is the weighted sum of the values: softmax(QKᵀ / √d) · V.

A causal mask hides later tokens, so the model can only look backward. That's what makes next-token training work. Multi-head attention runs this many times in parallel with different projections. Standard attention compares every token with every other, so its cost grows with the square of the context length.

Part 4 · The layers

Attention and lookup, stacked deep

A transformer repeats one block many times, often 30 to 100 or more. Each block has two parts. Attention moves information between tokens. A feed-forward network works on each token separately and is where much of the model's stored knowledge seems to live. Both add their results to a running vector for each token instead of replacing it.

What the weights are

Parameters

Every number in the model's matrices is a parameter, adjusted during training. Open models range from about a billion to hundreds of billions. Many labs don't publish the sizes of their largest models.

What the model knows

Compressed patterns

There's no database of facts inside. Knowledge is spread across the weights as patterns learned from text. That's why recall is usually right but can be confidently wrong, especially for rare facts.

What comes out

Logits

After the last layer, the final vector is compared with every token in the vocabulary. Each comparison gives a score, called a logit. Softmax turns the scores into probabilities that sum to one.

For engineers

Each block is roughly: x = x + Attention(Norm(x)), then x = x + MLP(Norm(x)). The additions form the residual stream, a shared workspace each layer reads from and writes to. Normalization keeps values in a stable range. The MLP usually expands the width about four times, applies a nonlinearity, then projects back down.

Many recent models replace the single MLP with a mixture of experts: several MLPs, with a router sending each token to a few of them. Total parameters grow, but each token only uses a fraction.

Part 5 · Choosing the next token

Temperature and top-p

The model produces probabilities; a sampler picks one token. Temperature reshapes the distribution: low makes the top choice dominant, high flattens everything. Top-p (nucleus sampling) keeps only the smallest set of tokens whose probabilities add up to p, cutting off the long tail of unlikely choices.

The horde is moving toward the ___

Illustrative scores. Grey bars are cut by top-p and can't be chosen.

Generation is this step in a loop. Each new token is appended and the whole sequence is processed again, which is why long answers take longer and why the first few tokens steer everything after them. Models cache the attention keys and values from earlier tokens, called the KV cache, so each new step only computes the new token.

Reasoning models use the same loop. They're trained to write out intermediate steps (thinking tokens) before the final answer, so the answer is conditioned on that work. More tokens of thinking costs more time, and often buys better answers on multi-step problems.

Part 7 · Memory

What the model can and can't remember

No memory between calls

The model itself is fixed after training. A chat feels continuous because the app resends the conversation every time. Features that "remember" you store notes and put them back into the prompt.

The context window

Everything the model can consider at once: instructions, conversation, documents, its own output. Windows range from thousands to over a million tokens, but quality often drops for details buried in the middle of very long inputs.

A knowledge cutoff

Training data stops at a date. Anything after that, and anything private to your organization, the model only knows if you supply it: in the prompt, through retrieval, or with tools.

Part 8 · Known weaknesses

Why LLMs fail the way they do

Each failure follows from the mechanism. Knowing the cause tells you the fix.

Confident fabrication

A plausible citation, figure or API that doesn't exist.

Why: the model produces likely-sounding text, and a fluent wrong answer can be very likely. Fix: give it sources (FM 7), ask for citations, and verify what matters.

Letter and number slips

Miscounting letters, mangling long arithmetic.

Why: it sees tokens, not characters or digits. Fix: let it use a calculator or code tool (FM 2, FM 4).

Sensitivity to wording

A small change in the prompt changes the answer.

Why: every word shifts the probabilities. Fix: say the reader, purpose and format explicitly (FM 1) and test prompts on many inputs.

Agreeing too readily

Changing a correct answer because you pushed back.

Why: training on human preferences can reward agreeableness. Fix: ask it to evaluate claims, not confirm them, and check against sources.

Different answers each run

The same prompt gives different results.

Why: sampling is random by design. Fix: lower temperature for factual tasks, and judge prompts by many runs, not one.

Out of date

Describes a version, price or role that has changed.

Why: the knowledge cutoff. Fix: provide current information or a search tool.
