Salvaged Records

The scavenging crews bring back paper: supply manifests, handwritten logs, faded intake forms, receipts, photos of whiteboards. The camp needs that paper as data. A vision-capable model can read almost any of it, and it will also fill an unreadable box with a confident guess. This manual covers how to get structured data out of documents and images, and how to prove it's right before anyone relies on it.

Who it's for

Engineers and analysts turning PDFs, scans, receipts, screenshots and charts into rows.

Time

About 75 minutes, half hands-on.

Bring

Python 3.10+, Ollama with gemma3 pulled (Field Manual 4), and five real documents you're allowed to process.

  • Use the cheapest reader that works.

    A PDF with a text layer needs no model at all. Classic OCR handles clean print. Save vision models for layout, handwriting and mixed content.

  • Schema in, checks out.

    Ask for a fixed JSON shape, then check that totals add up and dates parse. Anything that fails goes to a person.

  • Measure field by field.

    "It looks right" hides the one wrong digit. Score every field against a hand-labeled set before you trust a model or a change.

pypdf

Pure Python. PdfReader(path).pages[i].extract_text() returns a page's text layer, or almost nothing for a scan. That emptiness is your scan detector.

pdfplumber

Built on pdfminer.six. Gives every character's position, plus page.extract_tables(). Use it when you need coordinates or ruled tables from a text-layer PDF.

PyMuPDF

Imported as pymupdf (older code uses fitz). Fast text extraction and page rendering with page.get_pixmap(dpi=200). Licensed AGPL or commercial; check before you ship it.

Tesseract is the classic open-source OCR engine. Install the binary, then call it from Python with pytesseract. image_to_data returns each word with its box and a confidence score, which gives you provenance a vision model won't. Its docs say it works best on images of at least 300 DPI.
Part 2 · How the model sees

Images become tokens

A vision-language model cuts the image into a grid of small square patches, often 14 or 16 pixels on a side. Each patch becomes a vector the language model reads alongside your text. Many models then merge neighboring patches (2×2 is common) to save tokens.

Before any of that, the image is resized to fit the model's limit. Three consequences follow.

  • Cost grows with pixels. More patches means more tokens, more memory and slower answers.
  • Big pages get shrunk. A full page squeezed to the limit can leave fine print two or three pixels tall. The model then guesses, fluently.
  • Crop and split to buy resolution. Send one region or one page per call. Each piece gets the full pixel budget.

How models differ: Gemma 3 resizes every image to 896×896 and spends 256 tokens on it. Gemma 4 lets you pick a visual token budget from 70 to 1,120. Qwen2.5-VL uses 14-pixel patches merged 2×2, so one token per 28×28 pixel block. Hosted APIs publish their own formulas; read them before you budget.

Part 5 · Known misreads

How extractions go wrong

The model rarely returns gibberish. It returns clean, plausible JSON with one wrong value in it. These are the patterns to test for.

The invented value

A smudged signature comes back as a full name. A torn-off date comes back as a real date.

Fix: make every field nullable and say "use null if not visible; never guess." Label unreadable fields as null in your test set so a guess counts as an error.

Look-alike characters

1 and 7, 0 and O, 5 and S, 8 and B, a dropped decimal point. One digit off and the JSON still looks perfect.

Fix: constrain types (integers, patterns for IDs), cross-check arithmetic, and raise resolution on the region that holds numbers.

Swapped columns

Unit price lands in amount, or a narrow column shifts one cell left.

Fix: name columns in the schema with descriptions, and check qty × unit = amount on every row.

Merged or dropped rows

A wrapped description joins two rows into one. A row near a page break disappears.

Fix: ask for one item per printed row, check the item count when the form prints one, and check that the items sum to the total.

Ambiguous dates

03/11/2026 becomes November 3 or March 11 depending on the model's habits.

Fix: tell the model the source format, ask for ISO dates, and check that the date is plausible for the batch.

Helpful corrections

The form says 96.00 but the model "fixes" it to the computed 96.40. Now your check passes on a value nobody wrote.

Fix: instruct "copy exactly as written; don't calculate." Validation is your job, not the model's.

Lost in the long document

A 30-page PDF sent at once. Pages get shrunk, skipped or blended together.

Fix: one page per call, or one region per call for dense pages. Keep the page number with every value.

Loose
Extract the data from this receipt as JSON.
Tight
Extract this receipt using the given JSON schema. Copy values exactly as printed. If a field is unreadable, cut off or absent, use null. Don't calculate or correct anything. One item per printed line.

Tight

Tight

Confidence scores from the model aren't calibrated. If you ask a model to rate its own certainty, the number tells you little on its own. Route records to review on evidence you can check: failed rules, null required fields, disagreement between two models or two runs, and OCR word confidences where you have them.
Part 6 · Who else reads the paper

Documents carry people

Intake forms, receipts and logs hold names, addresses, signatures, account numbers and health details. An image carries everything in frame, including what you didn't mean to send: the next form on the desk, a face, a badge.

Know where it goes

Check which tools your organization has approved for this kind of data before you send a page anywhere. A local model keeps pages on your machine; a hosted API sends them to a provider under their terms.

Send less

Crop to the region you need. Mask fields you don't need before extraction. Don't ask for fields you won't use: every extracted field is data you now hold.

Treat text as data

A document can contain instructions aimed at your model, such as hidden text in a PDF or a note in an image. Extract into a schema, never let document text trigger tools, and validate the output.

    Pocket checklist

    Before the records go into the ledger

    • Every page is sorted: text layer, scan, or needs a vision model.
    • Originals are stored unchanged, and every value points back to its file and page.
    • The schema makes every field nullable, and the prompt forbids guessing.
    • Validation rules run on every record: arithmetic, dates, patterns, required fields.
    • Failures go to a review queue that a named person works through.
    • A hand-labeled test set of at least 50 documents, scored field by field, gates every model or prompt change.
    • The tools that see these documents are approved for the data in them.
