For squad leaders

Squad Orders

A coding agent is the most capable recruit in camp. It reads every file, runs commands, writes the fix and opens the pull request. It also does exactly what you said, stops the moment the work looks done, and loses track of your briefing once its pack gets too heavy. This manual covers how to brief, equip and supervise agents like Claude Code and Devin so they come back with work you can ship.

Who it's for

Engineers who've tried a coding agent and want reliable results, not occasional magic.

Time

About 60 minutes, plus the drills in your own repository.

Bring

Access to Claude Code or Devin, and a repository with tests you can run.

Part 1 · Know your recruits

Two ways to work with an agent

Both run the same loop: read, plan, change, run, check, repeat. They differ in where they work and how closely you supervise. Most teams use both styles.

At your side

Claude Code

Works in your terminal, IDE, the desktop app or the web, on your actual checkout. You watch it think, stop it with Esc, and redirect in seconds.

  • Best for: exploring unfamiliar code, debugging, design work where you'll change your mind, and anything you want to steer.
  • Your role: navigator. Short feedback loops, frequent course corrections.
Sent on a mission

Devin

A cloud teammate with its own machine. You assign work from the web app, Slack or Microsoft Teams, and it comes back with a pull request. You can check in and send new instructions mid-session.

  • Best for: well-scoped tasks with a checkable result. Devin's own rule of thumb: if it would take you three hours or less.
  • Your role: dispatcher. A clear brief up front, then review the result.

The line blurs. Claude Code can also run sessions in the cloud and in the background, and Devin can be steered while it works. Pick the style by how much you'll need to steer, not by product name.

Part 2 · The heavy pack

Context is the scarcest supply

Everything in a session (your messages, every file the agent reads, every command output) goes into one context window. As it fills, quality drops: early instructions slip and mistakes go up. Both Claude Code's and Devin's guidance say this. Load the pack below and see how you'd keep it light.

    Part 3 · The briefing

    Write orders an agent can finish

    Field Manual 1 applies in full: the agent fills every gap with the typical case. Coding agents add one rule above all others. Give it a way to check its own work. Without a test, build or screenshot to compare against, "looks done" is the only signal it has, and you become the test suite.

    
      
      
    
      
  
      
  
      
    
      Vague
      Fix the login bug.
      Briefed
      Users report login fails after a session times out. Look at token refresh in src/auth/. Write a failing test that reproduces it, then fix it and run the auth tests.
      
    
      Vague
      Add a calendar widget.
      Briefed
      Follow the pattern in WeatherWidget.tsx to add a calendar widget with month paging. Use only libraries already in package.json. Screenshot it next to the mockup and list the differences.
      
    
      Vague
      The build is broken.
      Briefed
      The build fails with this error: [paste]. Fix the root cause, not the symptom. Don't suppress the error. Confirm the build passes.

      Part 6 · Run a squad
      
    
      More than one agent at a time
      
  
      
  
      
    
      Split the mission
      Break a big project into independent tasks, one session each. Devin's docs recommend this, and note that long sessions degrade. In Claude Code, run each in its own git worktree with claude --worktree so edits don't collide.
      
    
      Writer and reviewer
      One agent writes; a second, in a fresh session, reviews the diff against the plan. A fresh reviewer isn't biased toward code it just wrote. Claude Code has a built-in /code-review skill; Devin has Devin Review.
      
    
      Fan out
      For large, repetitive changes, have the agent list the files, test the prompt on two or three, then run the rest. Claude Code offers /batch and the scriptable claude -p; Devin can delegate to managed Devins.
      
  
      
  
      Ask reviewers for real problems only. A reviewer told to find defects will usually find some, even in sound work. Ask it to flag only issues that affect correctness or a stated requirement, or you'll over-engineer chasing every comment.
      

      


      
  
      
    
      Part 7 · Known threats
      
    
      How agent sessions go wrong
      
  
      
  
      
    
      The junk-drawer session
      One task, then an unrelated question, then back again. The pack fills with noise.
      Fix: one task per session. In Claude Code, /clear between unrelated tasks; in Devin, start a new session.
      
    
      Correcting in circles
      You correct it, it's still wrong, you correct it again. The failed attempts now steer the session.
      Fix: after two failed corrections, start fresh with a better brief that includes what you learned.
      
    
      The bloated rulebook
      CLAUDE.md or Knowledge grows until the important rules get lost.
      Fix: for each line, ask whether removing it would cause a mistake. If not, cut it. Turn must-happen rules into hooks or CI.
      
    
      Looks right, isn't
      Plausible code that misses edge cases, accepted because nothing checked it.
      Fix: always give it a check, and ask for evidence: test output, commands run, screenshots. If you can't verify it, don't ship it.
      
    
      Endless scouting
      "Investigate this" with no scope. It reads hundreds of files and fills the pack.
      Fix: scope the question, or send a subagent to investigate and report back a summary.
      
    
      The open gate
      An unattended agent with broad permissions runs something irreversible.
      Fix: allow-list safe commands, sandbox the rest, keep secrets out of reach, and require human review before merge or deploy.
