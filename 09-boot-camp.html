Recruits aren't born, they're drilled

Boot Camp

Prompting tells a model what to do this time. Training changes the model itself. This manual covers both ends: watching a tiny model learn from scratch, so you can see what training actually does, then fine-tuning a real open model with LoRA so it reliably does one job your way. It also covers the most important step, which is deciding whether to fine-tune at all.

Who it's for

Engineers who've hit the limits of prompting and retrieval, or want to understand what training does.

Time

About 90 minutes, plus training time.

Bring

Python 3.10+, PyTorch, and for Part 4 a GPU with 8 GB or more, or a free hosted notebook with one.

Part 1 · Before you train anything

Pick the cheapest tool that works

Fine-tuning is powerful and often unnecessary. It's the slowest option to change, needs good data, and gives you a model to maintain. Each step up this ladder costs more.

ToolBest forCost to changeField manual
Better promptMost problems: format, tone, task clarity, examplesMinutesFM 1
Retrieval (RAG)Knowledge the model lacks, especially facts that changeHoursFM 7
Tools and agentsActions, live data, exact calculationHours to daysFM 2, 6
Fine-tuningConsistent style or format, a narrow skill, a smaller cheaper model matching a bigger one on one taskDaysThis one
Train from scratchA new language or domain at huge scale, or researchMonths and serious moneyPart 2, in miniature
Fine-tuning teaches behavior better than facts. It's good at "always answer in this format" and "write like our team." It's unreliable for "know our latest policy," because the facts get blurred into the weights and go stale. Use retrieval for facts.

Part 2 · Watch a model learn

Training from scratch, in your browser

This is a real model, trained live with gradient descent on a few paragraphs of camp logs. It's the simplest possible language model: it predicts each character from the one before it. Each step nudges its numbers to make the real next character a little more likely. Watch the loss fall and the samples go from noise to something camp-shaped.

What's happening, for engineers

    
The model is a table of logits W[a][b]: the score for character b following a. Loss is the average cross-entropy, −log p(next | current), over every character pair in the training text. Each step computes the exact gradient, softmax(W[a]) − onehot(b) summed over pairs, and subtracts learning rate × gradient.

    
A real LLM does the same thing with a transformer instead of a table, billions of parameters instead of a few thousand, a context of thousands of tokens instead of one character, and random mini-batches instead of the whole text. The loss curve, the overshoot at high learning rates and the overfitting gap all look the same.

  






  

    
Part 3 · The same thing, with a transformer

    
A tiny GPT in 60 lines of PyTorch

    
The browser model only sees one character back. This one uses a small transformer that sees 64 characters, so it can learn words and phrasing. Put any text file of a few hundred kilobytes in camp_logs.txt (a public-domain book works well) and run it. It trains on a laptop CPU in a few minutes, faster with a GPU.

  

  
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
device = "cuda" if torch.cuda.is_available() else "cpu"

text = open("camp_logs.txt", encoding="utf-8").read()
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for c, i in stoi.items()}
data = torch.tensor([stoi[c] for c in text])
split = int(0.9 * len(data))
train_data, val_data = data[:split], data[split:]   # hold out 10% to detect overfitting

CTX, DIM = 64, 128


def get_batch(source, n=32):
    ix = torch.randint(len(source) - CTX - 1, (n,))
    x = torch.stack([source[i:i + CTX] for i in ix])
    y = torch.stack([source[i + 1:i + CTX + 1] for i in ix])   # targets: the next character
    return x.to(device), y.to(device)


class TinyGPT(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.tok = nn.Embedding(vocab_size, DIM)
        self.pos = nn.Embedding(CTX, DIM)
        layer = nn.TransformerEncoderLayer(
            DIM, nhead=4, dim_feedforward=4 * DIM, batch_first=True, norm_first=True
        )
        self.blocks = nn.TransformerEncoder(layer, num_layers=4)
        self.head = nn.Linear(DIM, vocab_size)

    def forward(self, idx):
        T = idx.shape[1]
        h = self.tok(idx) + self.pos(torch.arange(T, device=idx.device))
        mask = nn.Transformer.generate_square_subsequent_mask(T, device=idx.device)
        h = self.blocks(h, mask=mask, is_causal=True)   # causal: only look backward
        return self.head(h)


model = TinyGPT(len(chars)).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)


def loss_on(source):
    x, y = get_batch(source)
    return F.cross_entropy(model(x).reshape(-1, len(chars)), y.reshape(-1))


for step in range(3000):
    model.train()
    loss = loss_on(train_data)
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 300 == 0:
        model.eval()
        with torch.no_grad():
            print(f"step {step:5d}   train {loss.item():.3f}   val {loss_on(val_data).item():.3f}")


@torch.no_grad()
def generate(prompt, n=300, temperature=0.8):
    model.eval()
    ids = torch.tensor([[stoi[c] for c in prompt]], device=device)
    for _ in range(n):
        logits = model(ids[:, -CTX:])[:, -1] / temperature
        nxt = torch.multinomial(F.softmax(logits, dim=-1), 1)
        ids = torch.cat([ids, nxt], dim=1)
    return "".join(itos[i] for i in ids[0].tolist())


print(generate(text[:20]))

  
Watch for the same things as in Part 2: loss falling, validation loss tracking training loss, and samples improving. If validation loss rises while training loss keeps falling, the model is memorizing; stop earlier or add data. For a fuller version, Andrej Karpathy's nanoGPT is the classic next step.






  

    
Part 4 · Fine-tuning a real model

    
LoRA: train a small add-on, not the whole model

    
Full fine-tuning updates every weight and needs memory for the weights, their gradients and the optimizer's state, roughly 16 bytes per parameter. LoRA (low-rank adaptation) freezes the model and trains small extra matrices beside each layer, typically well under 1% of the parameters. QLoRA also loads the frozen model in 4-bit precision, which lets a single consumer GPU fine-tune models that would otherwise need a server.

Rough GPU memory for the model plus training state, before activations, which add more with longer sequences and bigger batches. Treat these as orders of magnitude, not guarantees. Model shapes are typical for each size.

    

  

  
How LoRA works, for engineers

    
For a frozen weight matrix W of shape dout × din, LoRA learns B (dout × r) and A (r × din) and computes Wx + (α/r)·BAx. B starts at zero, so training begins from the original model exactly. Only A and B get gradients and optimizer state.

    
Apply it to all linear layers (target_modules="all-linear"), not just attention: research summarized in the TRL docs found attention-only LoRA underperforms even at higher rank. LoRA usually wants a learning rate around ten times higher than full fine-tuning, about 2e-4. After training you can merge BA into W and ship a normal model with no extra inference cost.

  






  

    
Part 5 · The training data

    
Your data is the model

    
The example teaches a model to turn rambling radio chatter into the camp's standard check-in format, a classic fine-tuning job: consistent format, hard to get reliably from a small model by prompting alone. Each line of a JSONL file is one example. Edit the data and the checker validates it.

  

  

    

      
      
      
    

    

      

      
    
    
    
  
    
  
    
    
    Quality beats quantity
    A few hundred clean, consistent examples often beat thousands of noisy ones. Every mistake in the data is a behavior you're teaching.
    
    
    Cover the real range
    Include the messy, short, long and unusual inputs people actually send, not just the tidy ones you thought of first.
    
    
    Hold some back
    Keep about 10% out of training to measure the result honestly. Never tune your settings by looking at the test set.
