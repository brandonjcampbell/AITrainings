All stations, one frequency

Common Frequency

Before the camps agreed on a radio protocol, every outpost wired its own set, and nothing talked to anything else. MCP, the Model Context Protocol, is that agreement for AI. Build a server once and any MCP host can use it: Claude Desktop, Claude Code, IDEs, or your own app. This manual covers how MCP works and walks you through building, testing and connecting a server in Python.

Who it's for

Engineers who want to give AI assistants access to their own tools and data.

Time

60 to 75 minutes, about half hands-on.

Bring

Python 3.11 or newer, uv or pip, and Claude Desktop or Claude Code to connect to.

Part 3 · What a station broadcasts

Tools, resources and prompts

A server can offer three kinds of things. The difference is who decides to use them.

Model decides

Tools

Actions the model can call, with typed inputs: check stock, log a sighting, query a database. The most common primitive, and the one that needs the most care, because tools can change things.

App decides

Resources

Read-only data addressed by a URI, like camp://rules. The host app or the user chooses which ones to load into context.

User decides

Prompts

Reusable templates the user picks, often from a menu or slash command, like "daily brief." They package a good prompt so people don't have to write it.

Part 5 · Don't let anything in

MCP security

An MCP server runs with your permissions, and everything it returns goes into the model's context. Treat a server like any program you install, and treat its output like untrusted input.

Untrusted stations

A server from an unknown source can read files, call APIs and send data anywhere you can.

Rule: install servers only from sources you trust, read the code or the publisher's docs, and pin versions.

Poisoned broadcasts

Text in a web page, ticket or tool description can contain instructions aimed at the model.

Rule: treat tool output as data. Keep a person in the loop for actions with side effects, and don't let one tool's output trigger another's write without review.

Too much reach

A server with full database or file access when it needs one table or one folder.

Rule: least privilege. Read-only by default, scoped credentials, separate tools for reading and writing.

Secrets in the wrong place

API keys in the launch arguments or committed config files.

Rule: pass secrets through the host's environment settings, and keep config files with keys out of git.

An open remote station

A Streamable HTTP server reachable by anyone who finds the URL.

Rule: require authorization on anything beyond localhost. The SDK supports OAuth for remote servers.

    # install (Python 3.11+)
uv add "mcp[cli]"              # or: pip install "mcp[cli]"

# server
from mcp.server import MCPServer
mcp = MCPServer("Name")
@mcp.tool()
def fn(arg: str) -> str:
    """What it does and when to use it."""
@mcp.resource("scheme://path")
@mcp.prompt()
mcp.run()                                         # stdio, for local hosts
mcp.run(transport="streamable-http", port=3001)   # http://127.0.0.1:3001/mcp

# develop and connect
uv run mcp dev server.py                          # MCP Inspector
uv run mcp install server.py                      # Claude Desktop
claude mcp add NAME -- uv run --with "mcp[cli]" mcp run /abs/path/server.py
/mcp                                              # inside Claude Code: check status

# client
from mcp import Client
async with Client("http://127.0.0.1:3001/mcp") as c:   # or Client(mcp) in tests
    await c.list_tools()
    await c.call_tool("name", {"arg": "value"})
